ARCHITECTURE

Clean boundaries stay explicit even when generation is configuration-first.

FoundationKit shares reusable code while each consumer owns runtime state, provider choices, migrations, credentials, policies and product semantics.

01
Domain

Entities, aggregate roots, value objects, domain events and exceptions with no framework dependency.

02
Application

Results, validation, repositories/specifications, UoW, capability composition, project/module contracts, generic CRUD orchestration and provider-neutral reliability contracts.

03
Infrastructure

Provider-neutral EF adapters, relational idempotency adapter, domain-event dispatch and module/EF composition helpers. The host still selects the concrete database provider.

04
WebApi

Problem Details, correlation, generic endpoints, request-pipeline helpers, concurrency/idempotency orchestration and runtime contract metadata.

05
Blazor

Typed API/error state plus the reusable Soft Orbit design system. It does not depend on server persistence.

BOUNDARY RULES
  • ✓ Lower layers do not depend upward for convenience.
  • ✓ Reusable packages do not own product migrations.
  • ✓ Consumers choose provider, schema and deployment.
  • ✓ Authorization stays server-authoritative.
  • ✓ Unsupported generation shapes fail closed.
  • ✓ Project runtime state is isolated by host.

PROJECT ISOLATION + RELIABILITY

Share Core code, never shared mutable project identity.

Each host owns one immutable project identity. Shared infrastructure is namespaced so independent products do not collapse into one runtime state.

Project identity

Immutable identity is registered per host; global mutable composition state is avoided.

Durable idempotency

Project-scoped acquisition/replay prevents one product from reusing another product's key space.

Optimistic concurrency

ROADMAP BOUNDARY

The approved Core vNext roadmap ends at Phase 12.

The final typed/read/frontend/tooling work is recorded as Phase 12 closure tracks—not Phase 13–16.

12.C1Typed transport

Runtime OpenAPI → deterministic C# typed client with requiredness, reliability headers and response metadata.

12.C2SQL read engine

Query/index intent, SQL-side execution and SQL-view-backed multi-table/report read models.

12.C3Frontend foundation

Reusable presentation/query state and Core Studio reference experience.

12.C4Tooling closure

Visual canonical Composer plus deterministic OpenAPI-wired generated Blazor shell.

Evidence-driven future capabilities

Files/documents, jobs/messaging, webhooks/realtime, multi-tenancy, external search/reporting, privacy/retention, money/numbering, Redis/PostgreSQL/object-storage providers and AI remain future product/provider-driven work. They are not silently claimed as delivered by the Phase 12 baseline.
