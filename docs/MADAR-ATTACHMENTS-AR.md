# مدار v0.9 — المرفقات والمستندات الآمنة

## الهدف

يضيف هذا الإصدار مرفقات مرتبطة بالحالات داخل `Madar` مع الحفاظ على صلاحيات الحالة نفسها وعدم تحويل الحاجة الأولى إلى حزمة عامة داخل FoundationKit.

## نموذج الوصول

المستخدم يستطيع عرض قائمة المرفقات أو تنزيل محتواها فقط إذا كان يستطيع أصلًا قراءة الحالة: منشئ الحالة، المكلّف الحالي، أو دور يملك `madar.cases.read-all`.

الحالة غير الموجودة والحالة التي لا يملك المستخدم صلاحية قراءتها تستخدمان نفس استجابة الإخفاء `not found`، لذلك لا تكشف واجهات المرفقات وجود حالة غير متاحة للمستخدم.

يبقى سجل المرفقات قابلًا للقراءة بعد إغلاق الحالة طالما بقيت صلاحية قراءة الحالة نفسها متحققة.

## سياسة الرفع الحالية

الحد الأقصى للملف الواحد هو **10 MiB**، والأنواع المسموحة في v0.9 هي:

| النوع | الامتداد المقبول |
|---|---|
| `application/pdf` | `.pdf` |
| `image/png` | `.png` |
| `image/jpeg` | `.jpg` أو `.jpeg` |
| `text/plain` | `.txt` |

لا يكفي اسم الملف وحده: يطابق Madar الامتداد مع `Content-Type` ويطبق فحص توقيع أساسي على PDF/PNG/JPEG، بينما يرفض النص الذي يحتوي على NUL في العينة الأولية. هذا الفحص **ليس بديلًا عن خدمة فحص برمجيات خبيثة في Production**.

اسم الملف الأصلي بيانات وصفية فقط ولا يستخدم كمسار تخزين. مفتاح التخزين ينشئه الخادم من معرف الحالة ومعرف المرفق، ولا تعرض واجهة API مفتاح التخزين أو مسار النظام.

## التخزين

الميتاداتا تحفظ في SQL Server داخل `madar.CaseAttachments`، بينما تحفظ البايتات عبر `ICaseAttachmentContentStore` الخاص بمنتج Madar.

التنفيذ الحالي هو نظام ملفات خاص مناسب لمرحلة Development/CI التجريبية. جذر التخزين قابل للضبط عبر:

```text
Madar:Attachments:StorageRoot
```

خارج Development يجب ضبط القيمة صراحة. ملف `deploy/madar-compose.yml` يستخدم volume خاصًا على `/app/data/attachments` ولا يضع الملفات تحت `wwwroot`، لذلك لا توجد روابط static مباشرة للمحتوى.

اختيار Object Storage أو KMS أو Malware Scanner أو CDN لبيئة Production مؤجل إلى قرار نشر حقيقي، ولا يدعي هذا الإصدار جاهزية Production لهذه الأجزاء.

## API

```text
GET  /api/cases/{caseId}/attachments
POST /api/cases/{caseId}/attachments
GET  /api/cases/{caseId}/attachments/{attachmentId}/content
```

الرفع يحتاج مصادقة وanti-CSRF ويستخدم سياسة write rate limiting الموجودة. التنزيل يمر دائمًا عبر Authorization داخل التطبيق قبل فتح المحتوى الخاص.

## التدقيق والخصوصية

يسجل Madar حدثين:

```text
madar.case.attachment-uploaded
madar.case.attachment-downloaded
```

خصائص التدقيق الإضافية تحتوي فقط على:

```text
attachmentId
```

ولا تنسخ اسم الملف، محتواه، مفتاح التخزين، مسار النظام، أو تفاصيل استثناءات مزود التخزين إلى Audit attributes.

## حدود v0.9

هذا الإصدار append-only من منظور المستخدم: لا توجد واجهة تعديل أو حذف أو versioning للمرفقات. كما أنه لا يضيف OCR أو بحثًا داخل الملفات أو signed URLs أو CDN أو مزود Object Storage أو Malware Scanner.

لا توجد حزمة `FoundationKit.Files` أو `FoundationKit.Storage`. يظل التنفيذ داخل Madar حتى يظهر دليل إعادة استخدام مستقل ومستقر يبرر استخراج قدرة عامة.

## التحقق

التحقق المطلوب للإغلاق يشمل اختبارات Domain/Application، وSQL/E2E فعليًا يثبت الرفع، حفظ الميتاداتا، التخزين الخاص، منع الوصول لمستخدم غير مرتبط، بقاء المرفق بعد إغلاق الحالة، التنزيل المصرح، وعدم تسريب المحتوى أو مسار التخزين في Audit.

نجاح CI أو هذه الاختبارات لا يمثل Production Approval أو اعتمادًا خارجيًا.
