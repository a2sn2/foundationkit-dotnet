## FoundationKit.Domain

Framework-free building blocks for entities, aggregate roots, value objects, exceptions, and domain events.

### Entity identity and equality

Stable identity-based equality with safe handling for transient entities.

Public surface: `Entity<TId>`

### Aggregate roots and domain events

Aggregate boundaries with in-memory domain-event queues dispatched after a successful save.

Public surface: `AggregateRoot<TId>`, `IDomainEvent`, `IHasDomainEvents`

### Value objects

Component-based equality for reusable immutable domain values.

Public surface: `ValueObject`

### Domain exceptions

Explicit exceptions for unrecoverable domain-rule violations.

Public surface: `DomainException`

## Project ideas

- **Internal operations platform** — Tasks, approvals, dashboards, and operational workflows backed by a structured API and product-owned persistence.
- **Customer support and messaging** — Conversation routing, tasks, escalation, and audit history with a clear boundary around external messaging integrations.
- **Agent onboarding and approval** — Requests, documents, reviews, and approval states without coupling the reusable core to one onboarding policy.
- **Fintech back office** — Internal financial operations, reviews, and reconciliation with classified results and explicit transaction boundaries.
- **Documentation and knowledge portal** — Content, versions, search, and public experiences with a consistent API and client state model.
- **Quality and release dashboard** — Testing, defects, releases, and operational decisions exposed through traceable API workflows.
- **Workflow and approval engine** — State transitions, approval rules, and domain events, with an outbox added when durable delivery is required.
- **Inventory and sales** — Products, stock, orders, and invoices using value objects and testable domain rules.

## Keeping the catalog current

When an implemented public capability changes:

1. update the code and tests;
2. update `catalog/foundationkit.catalog.json`;
3. run `dotnet run --project tools/FoundationKit.CatalogGenerator`;
4. update `CHANGELOG.md`.
